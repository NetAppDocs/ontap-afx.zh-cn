= 管理 AFX 存储系统的 FabricPool
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
在 AFX 系统上对 FabricPool 的持续管理类似于 AFF 和 FAS 系统。您需要监控空间利用率、管理卷并调整分层策略。对于 AFX 环境，有一些值得注意的新增内容，包括节点加入或离开 AFX 集群时的行为。



[[monitor-space-and-manage-volumes]]
== 监控空间并管理卷

与 AFX 一起用于监控容量层和性能层使用情况以及日常卷管理的步骤，通常与用于 ONTAP 的步骤相同。请注意，在 AFX 中，空间报告反映了分解架构。容量层空间信息可通过集群级和可用区报告获取，而不是通过管理员可见的聚合获取。



[[node-join-and-node-unjoin]]
== 节点加入和节点退出

在 AFX 系统上，节点操作具有 FabricPool 感知能力，这与 ONTAP 有显著不同。请注意以下行为：

* *节点加入。*当节点加入 AFX 集群且集群对象存储配置已存在时，会自动触发对象存储附加。如果附加失败，则节点加入操作也会失败。
* *节点退出。*当节点退出或从集群中删除时，数据将被标记为“defunct”。相关卷将使用 ZCVM 进行重新定位。废弃的对象元文件将被保留，以便其云对象保持可访问状态并可进行垃圾回收。
